# Umi-OCR 插件开发规范

## 第一章：概述

### 1.1 插件系统简介

Umi-OCR 插件系统是一种可扩展的架构设计，允许开发者通过 Python 包的形式为 Umi-OCR 添加新的识别引擎或功能模块。插件系统采用动态加载机制，通过插件控制器统一管理所有插件的注册、初始化和生命周期。

插件系统具有以下特点：
- 动态加载：插件在运行时自动发现和加载
- 统一接口：所有插件遵循相同的 API 接口规范
- 配置驱动：通过配置文件定义插件的各项参数
- 国际化支持：内置完整的国际化翻译机制
- 生命周期管理：支持插件的启动、停止和重启

### 1.2 插件分类与应用场景

当前 Umi-OCR 插件系统支持以下插件组别：

**OCR 插件（group: "ocr"）**
- 用途：提供光学字符识别功能
- 应用场景：支持不同的 OCR 引擎，如 PaddleOCR、RapidOCR 等
- 典型实现：封装本地 OCR 引擎可执行文件，提供统一的识别接口

**未来扩展**
系统架构支持添加更多插件组别，开发者可以根据需求扩展新的插件类型。

### 1.3 开发环境要求

**系统环境**
- 操作系统：Windows 7 及以上、Linux x64
- Python 版本：Python 3.7 及以上

**开发工具**
- 文本编辑器或 IDE（推荐支持 Python 语法高亮的编辑器）
- CSV 编辑器（用于国际化文件编辑）

**依赖库**
- Umi-OCR 核心库（通过插件系统自动导入）
- psutil（用于系统资源监控，可选）
- 其他第三方库（根据插件功能需求）

**必需的 Umi-OCR 内部模块**
- `plugin_i18n.Translator`：国际化翻译接口
- `umi_log.logger`：日志记录接口
- `call_func.CallFunc`：延迟执行接口（可选）

## 第二章：插件架构

### 2.1 插件目录结构

标准插件目录结构如下：

```
插件目录/
├── __init__.py              # 插件入口文件，必需
├── 插件名_api.py            # API 接口类实现，必需
├── 插件名_config.py         # 配置项定义，必需
├── i18n.csv                 # 国际化翻译文件，推荐
├── 插件名_pipe.py           # 引擎通信封装，根据需要
├── 插件名.exe               # 可执行文件，根据需要
├── models/                  # 模型库目录，根据需要
│   └── configs.txt          # 模型配置文件
└── README.md                # 插件说明文档，推荐
```

**文件说明**
- `__init__.py`：插件元信息定义，插件加载入口
- `*_api.py`：实现标准的 API 接口类，供 Umi-OCR 调用
- `*_config.py`：定义全局配置和局部配置
- `i18n.csv`：多语言翻译文件，采用 CSV 格式
- `*_pipe.py`：封装与外部引擎的通信逻辑
- 可执行文件：插件依赖的外部程序或脚本
- `models/`：存放识别模型或配置文件
- `README.md`：插件使用说明和部署指南

### 2.2 插件加载机制

插件加载由 `PluginsController` 统一管理，加载流程如下：

**步骤一：扫描插件目录**
- 插件控制器检查 `UmiOCR-data/plugins` 目录
- 列出所有子目录

**步骤二：识别有效插件**
- 检查每个子目录是否存在 `__init__.py` 文件
- 若存在，则认定为有效的插件包

**步骤三：动态导入插件**
- 使用 `importlib.import_module` 动态导入插件模块
- 捕获导入过程中的异常并记录错误

**步骤四：验证插件信息**
- 检查模块是否定义了 `PluginInfo` 字典
- 验证 `PluginInfo` 中必需的字段
- 确认插件组别是否在支持的范围内

**步骤五：注册插件**
- 将插件信息存入插件字典
- 将配置项存入配置字典
- 返回加载结果和错误信息

**步骤六：初始化 API 管理器**
- 将插件的 API 类注册到 API 字典
- 提供接口供其他模块调用

### 2.3 生命周期管理

插件生命周期包括以下阶段：

**初始化阶段**
- 插件被控制器加载
- API 类被注册到系统中
- 配置项被添加到设置界面

**实例化阶段**
- 当用户首次使用该插件时，系统调用 API 类的构造函数
- 传入全局配置参数 `globalArgd`
- 执行插件初始化逻辑

**启动阶段**
- 系统调用 API 的 `start` 方法
- 传入局部配置参数 `argd`
- 插件启动内部引擎或服务
- 若参数变化需要重启，则先停止再启动

**运行阶段**
- 系统调用识别方法：`runPath`、`runBytes`、`runBase64`
- 插件执行识别任务并返回结果
- 可能执行内存管理等维护操作

**停止阶段**
- 系统调用 API 的 `stop` 方法
- 插件释放资源、关闭引擎
- 清理临时数据

**销毁阶段**
- API 对象被垃圾回收
- 执行清理逻辑（如 `__del__` 方法）

### 2.4 依赖关系说明

**插件依赖 Umi-OCR 核心模块**
- `plugin_i18n.Translator`：用于国际化翻译
- `umi_log.logger`：用于日志记录
- `call_func.CallFunc`：用于延迟执行（可选）

**插件依赖第三方库**
- 根据插件功能需求选择合适的第三方库
- 常用库包括 `psutil`（系统资源监控）、`subprocess`（进程管理）等

**插件之间的依赖**
- 当前版本插件之间相互独立，不允许互相调用
- 未来版本可能支持插件间通信

**外部可执行文件依赖**
- OCR 插件通常依赖独立的可执行文件
- 可执行文件需放置在插件目录下
- 插件代码通过相对路径引用可执行文件

## 第三章：核心规范

### 3.1 PluginInfo 字典规范

`PluginInfo` 是插件的元信息字典，定义在 `__init__.py` 中。

**必需字段**

`group`
- 类型：字符串
- 说明：插件所属的组别
- 当前取值：`"ocr"`
- 示例：`"group": "ocr"`

`global_options`
- 类型：字典
- 说明：全局配置项，对所有任务实例生效
- 可为空字典或 `None`
- 示例：`"global_options": paddleocr_config.globalOptions`

`local_options`
- 类型：字典
- 说明：局部配置项，对单个任务实例生效
- 可为空字典或 `None`
- 示例：`"local_options": paddleocr_config.localOptions`

`api_class`
- 类型：类
- 说明：API 接口类，供 Umi-OCR 调用
- 必须实现第三章规定的接口方法
- 示例：`"api_class": PPOCR_umi.Api`

**PluginInfo 完整示例**

```python
from . import PPOCR_umi
from . import PPOCR_config

PluginInfo = {
    "group": "ocr",
    "global_options": PPOCR_config.globalOptions,
    "local_options": PPOCR_config.localOptions,
    "api_class": PPOCR_umi.Api,
}
```

### 3.2 API 类接口规范

API 类是插件的核心实现，必须实现以下接口方法。

**必需方法**

`__init__(self, globalArgd)`
- 功能：初始化 API 实例
- 参数：
  - `globalArgd`：字典，包含全局配置项的值
- 返回：无
- 规范：
  - 接收全局配置参数
  - 初始化内部状态
  - 验证依赖文件是否存在
  - 可以抛出异常表示初始化失败

`start(self, argd)`
- 功能：启动插件引擎
- 参数：
  - `argd`：字典，包含局部配置项的值
- 返回：字符串
  - 空字符串 `""` 表示启动成功
  - 以 `"[Error]"` 开头的字符串表示失败
- 规范：
  - 比较当前配置与目标配置
  - 若参数一致则无需重启
  - 若参数变化则先停止旧引擎再启动新引擎
  - 捕获异常并返回错误信息

`stop(self)`
- 功能：停止插件引擎
- 参数：无
- 返回：无
- 规范：
  - 释放引擎资源
  - 关闭子进程或连接
  - 清理临时数据

`runPath(self, imgPath)`
- 功能：对本地图片进行识别
- 参数：
  - `imgPath`：字符串，图片文件路径
- 返回：字典，识别结果
- 规范：
  - 确保引擎已启动
  - 执行识别任务
  - 返回标准格式的结果字典

`runBytes(self, imageBytes)`
- 功能：对图片字节流进行识别
- 参数：
  - `imageBytes`：bytes，图片字节数据
- 返回：字典，识别结果
- 规范：
  - 确保引擎已启动
  - 将字节流转换为引擎可识别的格式
  - 执行识别任务并返回结果

`runBase64(self, imageBase64)`
- 功能：对 base64 编码的图片进行识别
- 参数：
  - `imageBase64`：字符串，图片的 base64 编码
- 返回：字典，识别结果
- 规范：
  - 确保引擎已启动
  - 解码 base64 字符串
  - 执行识别任务并返回结果

**可选方法**

`__del__(self)`
- 功能：析构函数，清理资源
- 规范：
  - 调用 `stop()` 方法确保资源释放
  - 避免在析构中执行耗时操作

**返回结果格式规范**

识别结果必须为字典格式，包含以下字段：

`code`
- 类型：整数
- 说明：识别状态码
- `100`：识别成功
- `101`：识别成功但未检测到文字
- `900` 及以上：错误状态码

`data`
- 类型：列表或字符串
- 说明：识别结果数据
- 识别成功时为列表，每个元素代表一个识别文本块
- 失败时为错误信息字符串

**成功结果示例**

```python
{
    "code": 100,
    "data": [
        {"text": "识别文本", "score": 0.98},
        {"text": "另一行文本", "score": 0.95}
    ]
}
```

**失败结果示例**

```python
{
    "code": 901,
    "data": "错误信息描述"
}
```

### 3.3 配置系统规范

配置系统定义插件在设置界面中显示的配置项。

**配置字典结构**

配置字典为嵌套结构，顶层包含以下字段：

`title`
- 类型：字符串
- 说明：配置组的标题
- 必须使用 `tr()` 函数包裹以支持国际化
- 示例：`"title": tr("OCR 引擎设置")`

`type`
- 类型：字符串
- 说明：配置类型
- 当前固定为 `"group"`
- 示例：`"type": "group"`

其他字段为具体的配置项，键名为配置项的标识符。

**配置项通用属性**

`title`
- 类型：字符串
- 说明：配置项显示名称
- 必须使用 `tr()` 函数包裹
- 示例：`"title": tr("线程数")`

`default`
- 类型：任意类型
- 说明：配置项的默认值
- 根据配置项类型设定合适的默认值
- 示例：`"default": 4`

`toolTip`（可选）
- 类型：字符串
- 说明：配置项的工具提示
- 必须使用 `tr()` 函数包裹
- 示例：`"toolTip": tr("设置OCR引擎使用的线程数量")`

`advanced`（可选）
- 类型：布尔值
- 说明：是否为高级配置项
- 默认为 `False`
- 高级配置项在高级设置区域显示
- 示例：`"advanced": True`

**布尔型配置项**

适用场景：开关选项

属性：
- `title`：显示名称
- `default`：默认值（布尔值）
- `toolTip`：可选，工具提示

示例：

```python
"enable_mkldnn": {
    "title": tr("启用加速"),
    "default": True,
    "toolTip": tr("启用加速功能")
}
```

**整数型配置项**

适用场景：数值输入

属性：
- `title`：显示名称
- `default`：默认值（整数）
- `min`：可选，最小值
- `unit`：可选，单位字符串
- `isInt`：设为 `True` 表示整数类型
- `toolTip`：可选，工具提示

示例：

```python
"cpu_threads": {
    "title": tr("线程数"),
    "default": 4,
    "min": 1,
    "isInt": True,
    "toolTip": tr("设置线程数量")
}
```

**选项列表型配置项**

适用场景：从预设选项中选择

属性：
- `title`：显示名称
- `optionsList`：选项列表，格式为 `[[值, 显示文本], ...]`
- `toolTip`：可选，工具提示

示例：

```python
"language": {
    "title": tr("语言/模型库"),
    "optionsList": [
        ["models/config_chinese.txt", "简体中文"],
        ["models/config_en.txt", "English"]
    ]
}
```

**配置项命名规范**
- 使用小写字母和下划线
- 使用有意义的英文单词
- 避免使用保留字
- 同类型配置项保持命名风格一致

### 3.4 国际化规范

插件支持多语言界面，通过 `i18n.csv` 文件实现翻译。

**翻译文件格式**

`i18n.csv` 采用 CSV 格式，第一行为语言代码表头，后续行为翻译条目。

表头格式：`key,语言代码1,语言代码2,...`

当前支持的语言代码：
- `zh_CN`：简体中文（默认）
- `en_US`：英语
- `zh_TW`：繁体中文
- `ja_JP`：日语
- `ru_RU`：俄语
- `pt`：葡萄牙语
- `ta`：泰语

**翻译文件示例**

```csv
key,en_US,zh_TW,ja_JP
PaddleOCR（本地）,PaddleOCR (Local),PaddleOCR（本地）,PaddleOCR（ローカル）
启用MKL-DNN加速,Enable MKL-DNN acceleration,啟用MKL-DNN加速,MKL-DNN加速を有効にする
线程数,Number of threads,線程數,スレッド数
```

**翻译使用规范**

在配置文件中：
1. 导入 `Translator` 类
2. 创建翻译器实例
3. 使用 `tr()` 函数包裹所有需要翻译的文本

```python
from plugin_i18n import Translator

tr = Translator(__file__, "i18n.csv")

globalOptions = {
    "title": tr("PaddleOCR（本地）"),
    "type": "group",
    "enable_mkldnn": {
        "title": tr("启用MKL-DNN加速"),
        "default": True
    }
}
```

**翻译注意事项**
- 翻译文件使用 UTF-8 编码
- 所有用户可见的文本都需要翻译
- 配置项标题、工具提示、单位等都需要翻译
- 选项列表中的显示文本也需要翻译
- 保持原文与译文的语义一致

**翻译键命名规范**
- 使用配置项的原文作为翻译键
- 保持翻译键的唯一性
- 避免使用特殊字符和空格

### 3.5 错误处理规范

插件应正确处理各种错误情况，提供清晰的错误信息。

**错误返回规范**

所有可能失败的方法应返回错误信息：
- 启动失败：`start()` 方法返回以 `"[Error]"` 开头的字符串
- 识别失败：识别结果字典中 `code` 为错误码，`data` 为错误信息

**错误信息格式**

标准错误信息格式：`"[Error] 错误描述：详细信息"`

示例：
- `"[Error] Exe path does not exist."`
- `"[Error] OCR init fail. Argd: {...}"`
- `"[Error] Failed to generate API instance: ..."`

**异常处理规范**

在关键位置捕获异常：
- 文件读取操作
- 进程启动和通信
- 网络请求（如适用）
- 数据格式转换

异常处理模板：

```python
try:
    # 可能失败的操作
    result = do_something()
except Exception as e:
    return f"[Error] 操作失败：{e}"
```

**常见错误类型**

文件相关错误：
- 文件不存在：提示用户检查路径
- 文件无法读取：提示检查权限或文件格式

进程相关错误：
- 进程启动失败：提示检查可执行文件
- 进程崩溃：尝试重启或提示用户
- 通信超时：增加超时时间或提示网络问题

参数相关错误：
- 参数无效：提示用户检查配置
- 参数缺失：提供默认值或提示错误

**日志记录规范**

使用 `umi_log.logger` 记录关键日志：
- 错误日志：记录错误详情和堆栈信息
- 警告日志：记录非致命问题
- 信息日志：记录重要状态变化

示例：

```python
from umi_log import logger

try:
    result = do_something()
except Exception as e:
    logger.error(f"操作失败：{e}", exc_info=True, stack_info=True)
    return f"[Error] 操作失败：{e}"
```

## 第四章：开发流程

### 4.1 环境准备

**步骤一：准备 Umi-OCR 运行环境**
- 下载并安装 Umi-OCR
- 确保 Umi-OCR 可以正常启动和运行
- 记录 Umi-OCR 的安装目录

**步骤二：准备开发工具**
- 安装 Python 3.7 或更高版本
- 选择文本编辑器或 IDE
- 准备 CSV 编辑器（如 Excel 或文本编辑器）

**步骤三：创建插件开发目录**
- 在工作目录创建插件开发文件夹
- 将插件源码存放在此目录
- 方便后续测试和调试

**步骤四：准备依赖资源**
- 下载插件所需的可执行文件
- 准备模型库文件
- 整理配置文件

### 4.2 项目初始化

**步骤一：创建插件目录**
- 创建插件主目录，命名为插件标识符
- 建议命名格式：`平台_架构_插件名`
- 示例：`win7_x64_PaddleOCR-json`

### 9.1 版本号规范

插件版本号遵循语义化版本控制（Semantic Versioning）规范，格式为 `MAJOR.MINOR.PATCH`，其中：

- **MAJOR（主版本号）**：不兼容的 API 变更
- **MINOR（次版本号）**：向下兼容的功能性新增
- **PATCH（修订号）**：向下兼容的问题修正

**版本号示例**：
- `1.0.0`：初始版本
- `1.1.0`：添加新功能
- `1.1.1`：修复 bug
- `2.0.0`：API 重大变更

### 9.2 兼容性检查

插件应在初始化阶段检查与 Umi-OCR 核心版本的兼容性。

**版本检查实现**：

```python
import sys
from umi_log import logger

def check_compatibility():
    """检查插件与 Umi-OCR 版本的兼容性"""
    # 获取 Umi-OCR 版本信息（示例）
    umi_version = "2.0.0"

    # 插件支持的最低版本
    min_version = "1.8.0"

    # 插件支持的最高版本
    max_version = "2.1.0"

    if not is_version_compatible(umi_version, min_version, max_version):
        logger.error(f"Umi-OCR 版本 {umi_version} 不兼容，插件支持 {min_version}-{max_version}")
        raise Exception(f"版本不兼容：需要 Umi-OCR {min_version} 至 {max_version} 版本")

def is_version_compatible(current: str, min_version: str, max_version: str) -> bool:
    """检查版本是否在兼容范围内"""
    current_parts = list(map(int, current.split(".")))
    min_parts = list(map(int, min_version.split(".")))
    max_parts = list(map(int, max_version.split(".")))

    return min_parts <= current_parts <= max_parts
```

**在 API 类中的使用**：

```python
class Api:
    def __init__(self, globalArgd):
        try:
            check_compatibility()
        except Exception as e:
            raise Exception(f"插件初始化失败：{e}")
```

```python
import pkg_resources

def check_package_version(package_name: str, min_version: str) -> bool:
    """检查包版本是否符合要求"""
    try:
        version = pkg_resources.get_distribution(package_name).version
        return compare_versions(version, min_version) >= 0
    except pkg_resources.DistributionNotFound:
        return False

def compare_versions(v1: str, v2: str) -> int:
    """比较版本号"""
    v1_parts = list(map(int, v1.split(".")))
    v2_parts = list(map(int, v2.split(".")))

    for a, b in zip(v1_parts, v2_parts):
        if a > b:
            return 1
        if a < b:
            return -1

    return 0
```

import time
import psutil
from typing import Dict, Any

class PerformanceTester:
    def __init__(self, api):
        self.api = api
        self.results = []

    def test_single_image(self, image_path: str) -> Dict[str, Any]:
        """测试单张图片的识别性能"""
        # 预热
        self.api.start({})

        # 测试识别时间
        start_time = time.perf_counter()
        result = self.api.runPath(image_path)
        end_time = time.perf_counter()

        # 测试内存使用
        memory_usage = psutil.virtual_memory().percent

        # 测试 CPU 使用
        cpu_usage = psutil.cpu_percent(interval=1)

        return {
            "image": image_path,
            "time": end_time - start_time,
            "memory": memory_usage,
            "cpu": cpu_usage,
            "result_code": result.get("code")
        }

    def run_benchmark(self, image_paths: list) -> Dict[str, Any]:
        """运行基准测试"""
        for img_path in image_paths:
            try:
                result = self.test_single_image(img_path)
                self.results.append(result)
            except Exception as e:
                logger.error(f"测试失败 {img_path}：{e}")

        return self._calculate_statistics()

    def _calculate_statistics(self) -> Dict[str, Any]:
        """计算统计数据"""
        if not self.results:
            return {}

        times = [r["time"] for r in self.results]
        memories = [r["memory"] for r in self.results]
        cpus = [r["cpu"] for r in self.results]

        return {
            "total_images": len(self.results),
            "success_images": sum(1 for r in self.results if r["result_code"] == 100),
            "avg_time": sum(times) / len(times),
            "max_time": max(times),
            "min_time": min(times),
            "avg_memory": sum(memories) / len(memories),
            "avg_cpu": sum(cpus) / len(cpus)
        }
```

from typing import Any

class SecureDataHandler:
    """安全的数据处理类"""

    @staticmethod
    def sanitize_input(input_data: Any) -> Any:
        """清理输入数据，防止注入攻击"""
        if isinstance(input_data, str):
            # 移除危险字符和脚本标签
            sanitized = input_data.replace("<script>", "").replace("</script>", "")
            return sanitized
        elif isinstance(input_data, dict):
            return {k: SecureDataHandler.sanitize_input(v) for k, v in input_data.items()}
        elif isinstance(input_data, list):
            return [SecureDataHandler.sanitize_input(x) for x in input_data]
        else:
            return input_data

    @staticmethod
    def encrypt_sensitive_data(data: str, key: str) -> str:
        """加密敏感数据"""
        # 使用简单的加密示例，实际项目应使用更强的加密算法
        import base64
        from cryptography.fernet import Fernet

        # 生成密钥（实际应从安全位置获取）
        fernet = Fernet(base64.urlsafe_b64encode(key.ljust(32)[:32].encode()))
        return fernet.encrypt(data.encode()).decode()

    @staticmethod
    def decrypt_sensitive_data(encrypted_data: str, key: str) -> str:
        """解密敏感数据"""
        import base64
        from cryptography.fernet import Fernet

        fernet = Fernet(base64.urlsafe_b64encode(key.ljust(32)[:32].encode()))
        return fernet.decrypt(encrypted_data.encode()).decode()
```

**全局配置（Global Options）**
- 对所有任务实例生效的配置项
- 在全局设置中显示和配置
- 示例：线程数、内存限制

**局部配置（Local Options）**
- 对单个任务实例生效的配置项
- 在任务配置中显示和配置
- 示例：语言选择、方向纠正

**API 类（API Class）**
- 插件对外提供的接口类
- 必须实现规范定义的方法
- 被 Umi-OCR 直接调用

**引擎（Engine）**
- 插件调用的外部识别程序
- 通常是可执行文件或服务
- 由插件启动和管理

**翻译键（Translation Key）**
- 国际化文件中的标识符
- 使用原文作为键
- 用于查找对应的译文

**翻译器（Translator）**
- 提供国际化翻译功能的类
- 从 CSV 文件加载翻译
- 通过 `tr()` 方法进行翻译

**识别结果（Recognition Result）**
- OCR 识别返回的数据
- 标准格式为包含 code 和 data 的字典
- 包含识别文本和置信度信息

**错误码（Error Code）**
- 识别状态的数字标识
- 成功为 100 系列
- 错误为 900 及以上
- 用于判断识别是否成功
